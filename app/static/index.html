?Данные из детализации реализаций OZON. Прибыль = "К перечислению" − себестоимость×продано. Фактические комиссия/услуги OZON уже вычтены из "К перечислению" (они показаны справочными колонками). Точные начисления («Начисл.: продажа/комиссия/логистика/услуги», «На р/с (нач.)») загружаются из OZON API (OZON API ▸ Начисления) и дают реальную сумму к зачислению по каждому артикулу — это и есть ответ на вопрос «сколько Ozon перечислит за товар». «Прибыль (нач.)» = «На р/с (нач.)» − себестоимость×продано; пусто, если начислений по артикулу нет. «Δ нач. vs дет.» — расхождение начислений с детализацией: бывает при неполной детализации или возвратах. «На р/с (оценка)» — оценка по движению средств пропорционально доходу; точнее начисления, но начисления зачисляются с задержкой, поэтому за один и тот же месяц суммы отличаются. «Нераспределено» в статусе — начисления без артикула (страховка/размещение и товары без продаж в детализации). Рассчитано на ~2 недели ретроспективы, пока детализация не натянута за больший период.

Отправка товара (покупателю или на склад маркетплейса — контрагент WB/Ozon). Тот же формат, что и Приход.

Пожелание задаёт ручной итог отгрузки на WB: N шт раскидываются по размерам по выгоде, шаг отбирает размеры лесенки. Пусто — обычный план.
Экспорт в Excel ?В PDF по каждому товару — список всех размеров карточки WB: наличие (включая наш товар в пути) и «Дослать» — сколько не хватает до целевого запаса. Скорость продаж размера считается за окно из селектора (180 дней / 365 дней / всё время): короткое окно даёт нулевую скорость размерам, которые давно не продавались. Галка «Учитывать прибыльность» (включена по умолчанию) держит на WB четверть выбранного периода продаж и домножает цель на коэффициент по рентабельности товара: ≤ 0% — не подсортировываем совсем, 15% → ×1.0, 30% и выше → ×2.0. Коэффициент общий на товар — у размеров своей себестоимости нет. Убыточные и полностью закрытые товары в PDF не попадают. Если галку выключить, покрытие берётся из поля «Запас», а пустой размер получает 1 штуку. Пустой размер не остаётся пустым: если размер есть в карточке, но на WB его нет и продаж не было, в него закладывается 1 штука (кроме убыточных товаров) — иначе размер нельзя выбрать на карточке. Размеры, которых нет в карточке, но которые есть в продажах или остатках, тоже показываются. «—» вместо числа означает «дославать нечего». Режим «Для поставщика» (галка в меню «PDF ▾») печатает только фото, артикул, название и размеры с количеством к отгрузке (без остатков, цен, маржи и прочей аналитики) и убирает товары, где отгружать нечего — чтобы отправить поставщику список «что и сколько нам нужно». Файл с правками: в меню «PDF ▾» можно перетащить отредактированную выгрузку Excel (или выбрать её кнопкой) — состав карточек и значения печатаются из файла, «Итого дослать» задаёт колонка «WB дефицит» (пустая ячейка — расчёт по складу), отбраковка убыточных не применяется, фильтры таблицы игнорируются. Ozon пока не учитывается.

Спрос = продажи − возвраты за окно (шт/день) из детализаций Прибыльности. «Купить у поставщика» — довести общий запас (наш склад + WB/Ozon) до целевого числа дней; «Отгрузить» — сколько нужно отправить на каждый МП, чтобы закрыть его дефицит: источник — наш остаток и докупка, поэтому при нулевом своём остатке отгрузка не 0, если что-то нужно докупить (приоритет худшему остатку в днях). Товары без карточки на WB/Ozon считаются неактуальными и скрыты. Вид «Размеры» — разрез по размерам WB: продажи по размеру, остатки на складах МП по размеру и все размеры карточки WB (даже без продаж и остатков — со штрихкодом); спрос Ozon и «Купить у поставщика» считаются только по артикулу и в этом виде не выводятся. Для связки Ozon доступен только вид «артикулы».
