# Раздел «Автоматизация»

Три рабочих подраздела под общим dropdown «Автоматизация» в навигации. Все —
локальные операции над фотографиями Яндекса (тот же индекс, что у раздела
«Яндекс.Диск»), без обращения к API маркетплейсов.

| Вкладка (Tab id) | Назначение |
|---|---|
| `automation-foldering` | Фото для маркетплейса: раскладка фото по папкам WB/Ozon в ZIP |
| `automation-names` | Размножить имена: список имён фото `<артикул>-<n>.JPG` |
| `automation-crop` | Кроп изображений: обрезка фона + белая канва |

## Источник фотографий

Единый `app/services/photos.py::get_index()` — рекурсивный индекс локального
Яндекс.Диска (`settings.photos_root`, напр. `C:\YandexDisk\ФОТОГРАФИИ`).
Имена нормализуются: `<артикул>-<номер>.JPG`, ключ — артикул в верхнем регистре.
Реестр фото берётся не с API, а из локальной папки.

## 1. Фото для маркетплейса (`/api/automation/foldering/*`)

Вход: список артикулов (textarea, по одному в строке / через пробел) и/или файл
`.xlsx` / `.csv`. Колонка артикула распознаётся по имени (`Артикул`, `Article`,
`vendorCode`, `Артикул товара`); если есть парная колонка `Article_WB` —
nmID берётся из неё.

Опции:

- **Маркетплейс** — `WB` или `OZON`.
- **Какие фото отбираем?** — `ALL` / `ONLY_NEW`.
- **Порядок** — `ASCENDING` / `DESCENDING` (по номеру фото).
- **Leading nulls** — дописать ведущие нули до 3 знаков (`-2` → `-002`).
- **Change order** — поменять местами фото позиции 1 и N.

Конвенции имён в архиве:

- **WB**: папка `/<nm_id>/`, файлы `<артикул>-<n>.JPG` (nmID из `nm_articles`
  по артикулу; exact match, регистр не важен).
- **OZON**: папка `/<артикул>/`, файлы `<артикул>.JPG` (позиция 1),
  `<артикул>_<n>.JPG` (позиция n ≥ 2).

Вывод: один ZIP. Если распакованный объём > 500 МБ — ZIP из ZIP-ов
(`images_part_001.zip`, …), папки не дробятся между частями, плюс `README.txt`.

Эндпоинты:

- `POST /api/automation/foldering/preview` → JSON-сводка (найдено/нет фото).
- `POST /api/automation/foldering/build` → ZIP (attachment).

## 2. Размножить имена (`/api/automation/names/*`)

Генерация списка имён без изменения файлов. На каждый артикул —
`multiply` имён подряд, нумерация сквозная по повторяющимся артикулам.
Опция **КАПСЛОК** (по умолчанию включена): артикул в имени выводится в
верхнем регистре (`wlp-117` → `WLP-117-1.JPG`).

- `POST /api/automation/names/multiply` → JSON `{items, count}`.
- `POST /api/automation/names/download` → файл `.txt` (одно имя на строку).

## 3. Кроп изображений (`/api/automation/crop/build`)

Вход: загруженные файлы (multipart `files`) и/или артикулы с Диска. Для каждого
фото: EXIF-разворот → поиск верхней/нижней границы по белому фону (numpy) →
обрезка → resize по высоте → вставка на белую канву.

Категории (параметры портированы из finance `img_cropper.py`):

- `Одежда по пояс`
- `Обувь без модели`
- `Обувь без модели малыши`
- `Модель в полный рост`

Вывод: ZIP с обработанными изображениями (имена исходных файлов сохраняются).

## Технические заметки

- Бизнес-логика — в `app/services/` (`img_foldering.py`, `img_cropper.py`,
  `names_multiply.py`), эндпоинты — в `app/api/automation.py`.
- Достижимые модули: `photos`, `pillow`, `numpy`, `pandas`, `openpyxl`.
- Вкладки — формы, «Вид таблицы» не регистрируется (внесены в `NO_COLVIEW_TABS`).
